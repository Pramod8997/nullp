## False-positive and test-design findings

1. **Tests that reproduce implementation:**
   - `tests/test_hil_uart_corruption.py` generates frames with its own CRC helper and checks the helper against itself; it does not invoke the production PZEM Modbus parser/library.
   - `firmware/tests/test_main_host.c` defines replacement relay, heartbeat, arc-fault, and reconnect functions rather than compiling `firmware/esp32_node/src/main.cpp`.
   - `tests/test_security_penetration.py` and `tests/test_mqtt.py` exercise Python mocks for broker/auth behavior; they cannot prove Mosquitto ACL behavior.
2. **Tests that bypass or encode unsafe safety behavior:**
   - `test_pzem_watchdog_stays_disarmed_until_first_valid_read` and `test_bringup_gate7_dry_relay_close_stays_closed` intentionally require `ON` with a never-valid sensor. They are useful evidence of the bring-up contract, but are false positives if counted as production safety tests.
   - Several “safety” tests call `set_relay(True)` directly, bypassing the production command/actuation authority and freshness gate.
3. **Static tests and comments:**
   - `test_hardware_alignment.py` correctly strips C++ comments for its function-body safety assertions, which is good practice.
   - Other assertions still search raw source/config/document text, including status strings, command expressions, topic templates, and wiring prose. A quoted comment can satisfy those checks without executable behavior changing.
4. **Simulator versus physical claims:**
   - The firmware twin, HIL register injection, synthetic ML windows, mocked MQTT broker, and mocked browser all provide software evidence only. They do not validate mains behavior, relay contacts, brownout waveform, EMI, PZEM transaction timing, calibration, or physical enrollment.
   - The historical audit document’s “Production-Verified” and “100% pass” language must not be used as current physical evidence; the current release documents correctly retain `PHYSICAL VALIDATION: NOT RUN`.
5. **Weak assertions:**
   - “Does not raise,” “object exists,” “class is present,” and “mock selector was called” do not prove rejection, state integrity, task liveness, provenance, or deployment wiring. Each recommended regression above asserts an externally meaningful state transition or release invariant.
